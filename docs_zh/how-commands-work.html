命令工作原理

终端命令与斜杠命令的区别，以及它们各自在哪里运行

需要知道的一件事：OpenSpec 有两种命令，它们在两个不同的地方运行。

  • openspec ... 命令在你的终端中运行。（例如：openspec init。）
  • /opsx:... 命令在你的AI 助手的聊天中运行。（例如：/opsx:propose。）

如果你曾经在终端中输入 /opsx:propose 却什么也没发生，本文就是原因。你在跟 OpenSpec 的另一半说话。斜杠命令不是终端命令。它们是你给 AI 编程助手的指令，在你平时输入"添加一个登录表单"的同一个对话框中。

这个区分是新用户最常见的绊脚石，所以让我们把它讲得非常清楚。

两个半边

OpenSpec 是一个项目戴着两顶帽子。

CLI（终端半边）。一个名为 openspec 的程序，你从 shell 安装和运行。它设置你的项目、列出和验证变更、显示仪表板，并归档完成的工作。你在 iTerm、VS Code 终端、PowerShell 等任何运行 git 或 npm 的地方输入这些命令。

openspec init        # set up OpenSpec in this project
openspec list        # see active changes
openspec view        # open the interactive dashboard

斜杠命令（聊天半边）。像 /opsx:propose 和 /opsx:apply 这样的短命令，你在 AI 助手中输入。这些命令告诉 AI 遵循 OpenSpec 工作流：草拟提案、编写规格、根据任务清单构建、完成后归档。你在 Claude Code、Cursor、Windsurf、Copilot 或任何你使用的助手中输入这些命令。

/opsx:propose add-dark-mode    (typed in your AI chat)
/opsx:apply                    (typed in your AI chat)
/opsx:archive                  (typed in your AI chat)

这是用一张图展示的心智模型：

        YOUR TERMINAL                         YOUR AI ASSISTANT'S CHAT
   ┌──────────────────────┐               ┌──────────────────────────────┐
   │  $ openspec init     │   installs    │  /opsx:propose add-dark-mode  │
   │  $ openspec list     │  ──────────►  │  /opsx:apply                  │
   │  $ openspec view     │   commands    │  /opsx:archive                │
   └──────────────────────┘    & skills   └──────────────────────────────┘
        run openspec here                       run /opsx:* here

注意那个箭头。在终端中运行 openspec init 正是安装斜杠命令到你的 AI 工具中的方式。终端半边设置了聊天半边。之后，日常操作主要在聊天中进行。

"如何启动交互模式？"

没有单独的交互模式需要启动。这个问题经常出现，所以需要一个明确的答案。

你不需要进入特殊的 OpenSpec 模式。你只需像往常一样打开你的 AI 编程助手，然后在聊天中输入一个斜杠命令。斜杠命令就是你"进入" OpenSpec 的方式。你的助手识别它，加载匹配的 OpenSpec 技能，并开始遵循工作流。

所以真正的指令是：

  1. 在你的项目中打开你的 AI 编程助手（Claude Code、Cursor、Windsurf 等）。
  2. 在其聊天中输入 /opsx:propose，和你输入任何其他请求的地方一样。
  3. 观察自动补全：如果 OpenSpec 已安装，你会看到 /opsx:propose、/opsx:apply 等在你输入斜杠时出现。

就是这样。没有模式切换，没有守护进程启动，没有单独的窗口。

有一件事确实是交互的，它位于终端中：openspec view。它打开一个仪表板来浏览你的规格和变更。但那是一个查看器，不是你用来提议和构建的工具。构建是通过聊天中的斜杠命令完成的。

为什么存在这种分离

这值得理解，因为它解释了为什么 OpenSpec 能与 25+ 种不同的 AI 工具配合工作。

CLI 是引擎。它知道规则：变更文件夹长什么样，哪些工件依赖哪些，如何将增量规格合并到你的真相来源中。它在任何地方都一样。

斜杠命令是方向盘，每个 AI 工具的方向盘略有不同。Claude Code 称之为命令。Cursor 和 Windsurf 有自己的格式。有些工具称之为技能。当你运行 openspec init 时，OpenSpec 会为你选择的每个工具生成正确类型的文件，所以同样的 /opsx:propose 意图无论你用哪个助手都能工作。

这个设计的优势：你学一次工作流就能跨工具使用。权衡是：命令的确切语法在不同工具之间可能略有不同，这是下一节的内容。

各工具的斜杠命令语法

意图在任何地方都相同。标点符号不同。使用与你的助手匹配的形式。

工具输入方式
Claude Code/opsx:propose, /opsx:apply
Cursor/opsx-propose, /opsx-apply
Windsurf/opsx-propose, /opsx-apply
GitHub Copilot (IDE)/opsx-propose, /opsx-apply
Oh My Pi/opsx-propose, /opsx-apply
Kimi CLIskill-style, e.g. /skill:openspec-propose
Trae/opsx-propose, /opsx-apply

大多数工具使用冒号形式（/opsx:propose）或短横线形式（/opsx-propose）。少数工具将 OpenSpec 作为命名技能而非斜杠命令呈现；对于这些工具，你按名称调用技能。完整的每个工具列表，包括确切哪些文件写到哪里，请参见 支持的工具。

不确定时，在 AI 聊天中输入一个斜杠并查看自动补全。你的工具会显示它期望的形式。

命令是怎么来的：技能和命令

当你运行 openspec init（或 openspec update）时，OpenSpec 在你的项目中写入小文件，让你的 AI 工具能找到工作流。根据你的工具和设置，这些是技能、命令或两者兼有。

  • 技能位于 .claude/skills/openspec-*/SKILL.md 等位置。它们是新兴的跨工具标准：一个你的助手自动检测的指令文件夹。
  • 命令位于 .claude/commands/opsx/<id>.md 等位置。它们是较早的每工具斜杠命令文件。

你不必关心你的工具用哪种。你只需输入斜杠命令就能工作。但知道这些文件存在有助于在出问题时排查：如果你的命令消失了，通常意味着这些文件缺失或过时，openspec update 会重新生成它们。

参见 支持的工具了解每个工具的确切路径，以及迁移指南了解技能如何取代了较早的纯命令方式。

确认已安装

快速检查，从快到慢：

  1. 在 AI 聊天中输入一个斜杠。开始输入 /opsx 并观察自动补全建议。如果出现，就设置好了。
  2. 查看文件。对于 Claude Code，检查 .claude/skills/ 是否包含 openspec-* 文件夹。其他工具有自己的目录（支持的工具列出了它们）。
  3. 重新运行设置。从项目根目录运行 openspec update。这会重新生成你配置的工具的技能和命令文件。
  4. 重启你的助手。许多工具在启动时扫描技能和命令，所以一个新窗口可能就是缺少的步骤。

我到底有哪些命令？

默认情况下，OpenSpec 安装 core 斜杠命令集：

  • /opsx:explore：在确定变更之前与 AI 一起理清想法（不确定时是最好的第一步）
  • /opsx:propose：创建变更并一步草拟所有规划工件
  • /opsx:apply：通过执行任务清单来构建变更
  • /opsx:sync：将变更的规格更新合并到主规格中（通常是自动的）
  • /opsx:archive：完成变更并归档

一个好的默认节奏：不确定做什么时用 explore，然后 propose、apply、archive。探索优先指南解释了为什么那个起始步骤值得。

还有一个 expanded 命令集，面向需要更精细控制的人（/opsx:new、/opsx:continue、/opsx:ff、/opsx:verify、/opsx:bulk-archive、/opsx:onboard）。你用 openspec config profile 开启它，然后用 openspec update 应用。

刚接触这些？/opsx:onboard（在扩展命令集中）会在你自己的代码库上带你走完一个完整的变更，并讲解每个步骤。这是最友好的入门介绍。

每个命令的详细说明，请参见 命令。何时用哪个，请参见 工作流。

一次干净的首次运行

整合起来，这是整个序列，每步标注了它在哪里执行。

TERMINAL   $ npm install -g @fission-ai/openspec@latest
TERMINAL   $ cd your-project
TERMINAL   $ openspec init
              (installs slash commands into your AI tool)

AI CHAT      /opsx:explore
              (optional: think the idea through with the AI first)

AI CHAT      /opsx:propose add-dark-mode
              (AI drafts proposal, specs, design, tasks)

AI CHAT      /opsx:apply
              (AI builds it, checking off tasks)

AI CHAT      /opsx:archive
              (change is merged into your specs and filed away)

两个终端步骤完成设置。然后你在聊天中操作。这就是节奏。
